# Улучшение штрафов за прокачку серых навыков

## Проблема

Ранее была реализована неправильная логика штрафов за прокачку серых навыков:
- Высокие штрафы применялись к низкоуровневым серым навыкам (до 20)
- Низкие штрафы применялись к высокоуровневым серым навыкам (после 20)

Это противоречило основной задаче: **предотвратить прокачку серых навыков выше уровня 20**, где они начинают создавать проблемы для общей равномерной прокачки.

## Решение

### 1. Исправление шкалы штрафов для серых навыков

**Новая логика:**
- Уровни ≤5: штраф 1.0 (низкий)
- Уровни 6-10: штраф 1.2 (низкий) 
- Уровни 11-20: штраф 1.5 (умеренный) - *все еще приемлемо*
- Уровни >20: постепенно возрастающие штрафы:
  - 21-50: штраф 3.0 (высокий)
  - 51-100: штраф 4.0 (очень высокий)
  - 101-200: штраф 4.5 (экстремально высокий)
  - >200: штраф 5.0 (максимальный)

### 2. Введение позиционных коэффициентов

Добавлена функция `get_position_penalty_multiplier()` которая:
- Возвращает множитель 1.0 для обычных позиций
- Возвращает 1.1 для позиций DMC или MC (центральные полузащитники)
- Возвращает 1.2 для игроков с 2+ центральными позициями (DMC, MC, AMC)

Это позволяет более точно регулировать штрафы для сложных позиционных комбинаций.

## Преимущества нового подхода

1. **Логичная шкала штрафов**: до 20 уровня - нормально, после 20 - высокие штрафы
2. **Позиционные коэффициенты**: учитывают специфику разных ролей
3. **Балансировка**: игроки с несколькими центральными ролями получают дополнительные штрафы
4. **Поддержание равномерности**: белые навыки продолжают развиваться равномерно
5. **Профилактика проблем**: серые навыки выше 20 уровня эффективно подавляются

## Результаты тестирования

Симуляции показали:
- Белые навыки развиваются равномерно у всех типов игроков
- Серые навыки до 20 уровня остаются управляемыми
- Высокоуровневые серые навыки (>20) эффективно подавляются
- Позиционные коэффициенты позволяют точнее настраивать развитие
- Игроки с несколькими центральными позициями получают повышенные штрафы для баланса

## Влияние на производительность

- Изменения не влияют на производительность алгоритма
- Добавление позиционного множителя минимально влияет на вычисления
- Поддерживается обратная совместимость
