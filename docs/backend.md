# Документация Backend части

## Структура
Backend реализован как Flask приложение с REST API и бизнес-логикой в доменных классах.

### Файлы
- `web/app.py` - основное Flask приложение с маршрутами
- `domain/` - бизнес-логика (игроки, планировщик тренировок)
- `storage/` - репозитории для хранения данных
- `config/` - конфигурационные данные (позиции, навыки, тренировки)

## Маршруты
### GET /
Перенаправляет на страницу списка игроков

### GET /players
Отображает список всех игроков

### GET/POST /players/new
Создание нового игрока

### GET/POST /players/<player_id>
Отображение и редактирование деталей конкретного игрока

### POST /players/<player_id>/accept_training
Применение одной тренировки к игроку

### POST /players/<player_id>/accept_all_trainings
Применение всех тренировок из плана к игроку

### POST /players/<player_id>/update
Асинхронное обновление навыков и получение обновленного плана

## Доменные классы
### Player (domain/player.py)
- Хранит информацию об игроке (имя, позиции, навыки)
- Методы для применения тренировок
- Расчет средних значений навыков

### TrainingRecommender (domain/training_recommender.py)
- Генерация плана тренировок на основе текущих навыков
- Алгоритм балансировки развития навыков
- Приоритизация отстающих навыков

### TrainingPlanner (domain/training_planner.py)
- Реализует логику планирования тренировок
- Улучшенный алгоритм для предотвращения дисбаланса

## Хранение данных
### PlayerRepository (storage/player_repository.py)
- CRUD операции с игроками
- Сохранение в JSON файл
- Загрузка всех игроков

## Конфигурация
### config/skills.py
- Определение всех доступных навыков

### config/positions.py
- Определение позиций и соответствующих им белых навыков

### config/trainings.py
- Определение тренировок и их влияния на навыки

## Особенности реализации
- Все данные хранятся в JSON файле
- Используется объектная модель для представления игрока
- Алгоритмы тренировок учитывают текущий уровень навыков
- Система балансировки предотвращает чрезмерное развитие отдельных навыков
